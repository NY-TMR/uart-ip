# UART v1 任务书

## 1. 目标与兼容范围

UART v1 应能直接替换现有 SoC 中的 `uart` 模块。保留模块名、对外端口的名称、方向与位宽，以及参数 `CLK_FREQ`、`BAUD` 的名称与默认值。现有 BRAM 和 DDR2 系统的 UART 接线、寄存器地址及发送程序应继续适用。边界行为以本文已确认的规则为准。

本版重点为 TX 和分频行为。RX 保留旧路径，沿用 `RXD` 和 `irq` 的现有行为。RX 采样缺陷的修复与 AXI4 外设接入分别后续评审。

## 2. TX 行为

发送端有一个等待字节的容量，以及发送当前帧所需的状态。`tx_full` 表示等待槽有字节，`tx_busy` 表示当前帧正在发送。两者可同时为 `1`，也可在当前帧仍在发送时出现 `tx_full=0`。

### 2.1 接收与启动

1. 在时钟上升沿，若复位已释放、`write_en=1`、`addr=0x0`，且沿前等待槽为空，则接收 `wdata[7:0]`，并在沿后置位 `tx_full`。
2. 若沿前等待槽已满，该沿不接收新字节，即使该沿同时将等待字节搬入发送器。
3. 若沿前发送器空闲且等待槽有字节，则在该沿取出等待字节并开始发送起始位。刚入队的字节最早在下一个上升沿开始发送。
4. 等待字节被取出的上升沿清除 `tx_full`。在当前帧发送期间，等待槽可重新接收一个字节。

### 2.2 帧格式与完成

发送格式为 8N1，线路空闲为高，起始位为低，随后发送 8 个数据位，最低位先发，停止位为高。

从发送启动的上升沿开始，每个位均占 `16 × DIV` 个系统时钟周期。起始位与后续位等长，其长度与启动前的分频计数相位无关。例如，系统时钟为 50 MHz、`DIV=27` 时，每位占 432 个系统时钟周期。

停止位持续满一个位时间后，在对应的上升沿清除 `tx_busy`。若等待槽已有下一字节，则在随后的上升沿开始下一帧。

### 2.3 发送复位

在 `rst_n=0` 的时钟上升沿，停止发送并清空等待槽，将 `txd` 恢复为高电平，并清除 `tx_busy` 与 `tx_full`。正在发送的帧允许截断，复位前未发完或仍在等待的字节不自动重发。

## 3. 分频与寄存器接口

### 3.1 分频配置

复位时，`DIV` 恢复为 `CLK_FREQ ÷ (16 × BAUD)` 的整数部分。复位值应在 1 至 65535 之间。不能得到此范围内复位值的参数组合应在验证时报告错误。

在对 `DIV` 执行写入的上升沿，仅当沿前 `tx_busy=0`、`tx_full=0`，且 `wdata[15:0]` 非零时，才更新 `DIV` 为 `wdata[15:0]`。其余情况下保持原值。现有模块接口不提供写入拒绝响应。

### 3.2 寄存器兼容

| 偏移 | 寄存器 | 行为 |
|---|---|---|
| `0x0` | `TXD` | 写入按 §2.1 接收字节。读回 bit 0 为 `tx_full`。 |
| `0x4` | `RXD` | 保留旧版读回、读后清除及接收状态行为。 |
| `0x8` | `STAT` | bit 0 为 `tx_full`，bit 1 为 `tx_busy`，bit 2 和 bit 3 保留旧接收状态含义。读取 `STAT` 无副作用。 |
| `0xC` | `DIV` | 低 16 位读回当前分频值，写入遵循 §3.1。 |

`rdata` 保留按局部地址选择的组合读回行为。对于 `addr=0x0`，即使 `read_en=0`，`rdata[0]` 也须反映等待槽是否已满。现有 DDR2 SoC 依赖此位决定何时发出 `TXD` 写使能。BRAM 系统仍沿用现有软件发送间隔。

## 4. 独立开发与待定事项

计划使用 `project/uart_ip/` 开展独立开发，以现有 UART 接口模拟 SoC 访问，再回到 CPU 项目检查替换兼容性。寄存器访问与串行发送的职责分别描述。是否划分为独立 Verilog 模块，以及内部信号命名，暂缓决定。

TX 电路结构仍处于设计讨论阶段。具体 RTL、testbench、系统接入和验收方案待分别确定。
